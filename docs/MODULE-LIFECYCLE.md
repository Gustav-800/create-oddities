# 模块生命周期 / Module lifecycle

0.2.0 的模块按“是否注册游戏内容”分成两类。

## 行为模块

例如：

- `typewriter_keyguard`
- `speed_display`

它们不注册新物品/方块，可以在运行时读取配置并立即生效。  
配置开关关闭后，模块的交互/显示逻辑停止，但已存在的方块实体数据仍然保留，重新开启后可以继续使用。

## 内容模块

未来的新物品、方块、配方、创造模式标签等属于内容模块。

Minecraft 的注册表在游戏启动后不能安全地注销物品/方块，所以内容模块必须遵循：

1. **注册始终发生**：无论开关是否打开，注册代码都执行，避免进入世界时注册表缺失。
2. **开关只控制可见性和行为**：关闭时隐藏创造模式入口、禁用配方/掉落/交互，而不是移除注册项。
3. **状态在进入世界时冻结**：`OddityModule.requiresWorldReload()` 返回 `true` 的模块，其启用状态在进入世界时取一次快照；配置菜单中的修改不会立即改变当前世界。
4. **退出世界并重新进入后生效**：重新进入时重新读取快照。已经在世界中的物品不会凭空删除；关闭内容模块后，旧物品仍然存在，但不再能正常使用或获得。

## 配置

- 行为模块可以在运行时立即关闭。
- 内容模块的配置项应标注“进入世界后生效”。
- 关闭内容模块后，已存在的物品/方块不应导致崩溃；相关逻辑必须 fail-open（检测不到注册内容时直接跳过）。

## 当前状态

0.2.0 还没有内容模块；这个约束先记录在模块接口和文档中，0.3.0 开始加入新物品时必须遵守。
